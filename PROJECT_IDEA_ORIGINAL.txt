An agentic RAG platform: you upload documents, and you can ask questions in plain English and get streaming, citation-backed answers that are grounded in those documents — with an agent layer that routes different kinds of questions to different strategies.
A company has thousands of internal documents. People can’t find anything. Keyword search misses paraphrase (“time off policy” vs “vacation leave”); a raw LLM hallucinates and can’t cite sources. This platform ingests the documents, retrieves the genuinely relevant passages, and has an LLM answer only from those passages — with [1][2] citations back to the source, so answers are verifiable instead of invented.
Stack: React 18 + TypeScript + Vite + Tailwind (frontend) · Java 17 + Spring Boot 3.3.5 (backend) · PostgreSQL 16 + pgvector · Redis · MinIO/S3 · nginx · Docker Compose locally, Terraform/ECS Fargate for AWS.
Upload path: file → nginx → backend → stored in MinIO → deduplicated by content hash → status UPLOADED. An async pipeline then extracts text (PDFBox), splits it into overlapping chunks, embeds each chunk via OpenAI into a 1536-dim vector, and stores it in Postgres with an HNSW index. Status walks UPLOADED → PROCESSING → COMPLETED.
Query path: your question gets embedded → Postgres finds the nearest chunks by cosine similarity and by full-text keyword match → the two result sets are fused by Reciprocal Rank Fusion → the top chunks are assembled into a context block within a character budget → the LLM streams an answer token-by-token over Server-Sent Events, with citations pointing back to the chunks used.

5. Embeddings & vector search — OpenAI embeddings with retry/backoff/rate-limiting, vector(1536) column, HNSW cosine index.
6. RAG — SSE streaming answers with numbered citations, context-budget assembly.
7. Hybrid search — Postgres full-text (tsvector + GIN) fused with vector search via RRF; degrades to keyword-only when embeddings are off.
8. Agentic RAG — a router classifies each question and dispatches to one of four agents: Retrieval, SQL (safe templated metadata queries), Research (decompose → retrieve per sub-question → synthesize), Summarization. Bounded memory, per-step error isolation, full execution trace.
9. Operational tooling — thumbs-up/down feedback with metrics, admin dashboard (stats/users/documents/audit/feedback), Redis caching, Prometheus metrics.
10. AWS deployment — Terraform for VPC/ECS Fargate/RDS/ElastiCache/ALB/Secrets Manager, GitHub Actions OIDC pipeline, deployment doc with cost (~$210/mo staging) and DR targets.
- Why hybrid search beats vector-only: pure semantic search fails on exact tokens — error codes, IDs, product names. Keyword search fails on paraphrase. RRF fuses them by rank, so you never have to normalize two incompatible scoring scales. This is your strongest technical talking point.
- Why the SQL agent is safe: it never executes model-generated SQL. The LLM only picks an intent; the actual query is a pre-written, parameterized, owner-scoped template. That eliminates the injection surface entirely — a security instinct most candidates at your level don’t show.
